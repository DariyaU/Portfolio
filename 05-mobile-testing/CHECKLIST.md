# QA checklist — «ПО Ремонт» Android MVP

Чек-лист подготовлен для регрессионной и приёмочной проверки pet-project «ПО Ремонт».

## 1. Запуск и главный экран

- [ ] Приложение запускается без ошибки на поддерживаемом Android-устройстве.
- [ ] Главный экран отображается корректно.
- [ ] Доступен переход к текущему проекту ремонта.
- [ ] Доступен переход к общему списку дефектов.
- [ ] Доступен переход к справочнику материалов.

## 2. Проект ремонта

- [ ] Можно создать новый проект.
- [ ] Созданный проект сохраняется.
- [ ] После перезапуска приложения сохранённый проект доступен.
- [ ] Можно продолжить ранее созданный проект.
- [ ] Данные проекта отображаются без потерь после повторного открытия.

## 3. Помещения и этапы

- [ ] Отображается список помещений проекта.
- [ ] Для помещения отображаются доступные этапы ремонта.
- [ ] Переход между помещениями выполняется корректно.
- [ ] Переход между этапами выполняется корректно.
- [ ] Прогресс по помещению соответствует состоянию проверок.
- [ ] Прогресс обновляется после изменения результата проверки.

## 4. Чек-лист проверки

- [ ] Чек-лист выбранного этапа открывается.
- [ ] Проверке можно присвоить успешный результат.
- [ ] Проверку можно пропустить, если такой сценарий предусмотрен.
- [ ] Для проверки можно зафиксировать дефект.
- [ ] После изменения результата статус сохраняется.
- [ ] После возврата на предыдущий экран результат не теряется.
- [ ] Итоговый прогресс корректно учитывает состояние проверок.

## 5. Дефекты

- [ ] Дефект можно создать из соответствующей проверки.
- [ ] Можно заполнить описание дефекта.
- [ ] Дефект связан с нужным помещением и этапом.
- [ ] Дефект отображается в общем списке замечаний.
- [ ] Статус дефекта отображается корректно.
- [ ] Изменение статуса сохраняется.
- [ ] К дефекту можно добавить фотографию.
- [ ] Добавленная фотография корректно отображается после сохранения.
- [ ] Повторное открытие дефекта не приводит к потере данных.

## 6. Список замечаний и фильтрация

- [ ] Общий список содержит созданные дефекты.
- [ ] Данные дефекта совпадают с данными в исходном пользовательском сценарии.
- [ ] Фильтрация не скрывает подходящие записи ошибочно.
- [ ] После изменения статуса дефекта список обновляется корректно.

## 7. PDF-отчёт

- [ ] PDF-отчёт формируется без ошибки.
- [ ] В отчёте присутствуют данные текущего проекта.
- [ ] В отчёте корректно отображаются найденные дефекты.
- [ ] Данные в PDF соответствуют данным в приложении.
- [ ] Повторное формирование отчёта не ломает пользовательский сценарий.

## 8. Справочник

- [ ] Справочник открывается без подключения к сети.
- [ ] Список материалов отображается.
- [ ] Карточка выбранного материала открывается.
- [ ] Возврат из карточки не сбрасывает основной пользовательский сценарий.

## 9. Навигация и UX

- [ ] Кнопка Back приводит на ожидаемый экран.
- [ ] Пользователь не попадает в экран без понятного пути возврата.
- [ ] Основные действия доступны без неожиданных блокировок.
- [ ] Подписи, статусы и элементы управления соответствуют назначению экрана.
- [ ] Реализация основных экранов не противоречит макетам Figma.

## 10. Быстрый smoke перед демонстрацией

- [ ] Запуск приложения.
- [ ] Открытие/создание проекта.
- [ ] Открытие помещения и этапа.
- [ ] Прохождение одной проверки.
- [ ] Создание дефекта с описанием.
- [ ] Просмотр дефекта в общем списке.
- [ ] Формирование PDF-отчёта.
- [ ] Перезапуск приложения и проверка сохранности данных.

> Чек-лист является портфолио-артефактом для pet-project и не относится к коммерческому проекту работодателя.
