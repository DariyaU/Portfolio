# Test cases — REST API

Сценарии составлены по сохранённым учебным коллекциям Postman. Они отражают то, что присутствует в исходных материалах, без добавления неподтверждённых результатов.

| ID | Сценарий | Метод | Проверка |
|---|---|---|---|
| API-TC-001 | Найти питомцев по валидному статусу | GET | Успешный ответ и список данных |
| API-TC-002 | Передать невалидный статус питомца | GET | Обработка некорректного значения |
| API-TC-003 | Получить питомца по ID | GET | Path parameter и ответ API |
| API-TC-004 | Создать питомца | POST | JSON body и успешное создание |
| API-TC-005 | Обновить данные питомца | PUT | JSON body и изменение ресурса |
| API-TC-006 | Удалить питомца | DELETE | Удаление ресурса и HTTP-ответ |
| API-TC-007 | Передать данные пользователя в JSON | POST | Request body с пользовательскими данными |
| API-TC-008 | Передать данные пользователя через query parameters | POST | Query parameters и HTTP-ответ |
| API-TC-009 | Проверить запрос с авторизацией | GET/POST | Передача параметров авторизации |

## Что здесь проверяется

Для каждого запроса при практическом выполнении следует фиксировать:

- HTTP method;
- URL и endpoint;
- path/query parameters;
- request body;
- HTTP status code;
- структуру response body;
- соответствие фактического результата ожидаемому;
- корректность обработки негативных входных данных.

**Важно:** наличие сценария в этом файле не означает, что результат его выполнения был подтверждён в исходной коллекции. Это описание учебной практики и структуры проверок.
