# Checklist — REST API

## Request

- [ ] HTTP method соответствует операции
- [ ] URL/endpoint указан корректно
- [ ] Path parameters передаются корректно
- [ ] Query parameters передаются корректно
- [ ] Headers соответствуют запросу
- [ ] JSON body имеет ожидаемую структуру
- [ ] Обязательные поля присутствуют
- [ ] Типы данных полей соответствуют контракту

## Response

- [ ] HTTP status code соответствует ожидаемому сценарию
- [ ] Response body присутствует там, где ожидается
- [ ] Content-Type соответствует ответу
- [ ] JSON синтаксически корректен
- [ ] Структура response body соответствует контракту
- [ ] Ключевые поля присутствуют
- [ ] Значения ключевых полей корректны
- [ ] Ошибка возвращается в ожидаемом формате

## Negative testing

- [ ] Невалидное значение параметра
- [ ] Отсутствует обязательный параметр
- [ ] Некорректный идентификатор
- [ ] Некорректное значение enum/status
- [ ] Пустое значение
- [ ] Некорректный JSON body
- [ ] Проверка соответствующего HTTP-кода ошибки

## CRUD

- [ ] Create — POST
- [ ] Read — GET
- [ ] Update — PUT
- [ ] Delete — DELETE
- [ ] После Create можно получить созданный ресурс
- [ ] После Update изменённые данные возвращаются корректно
- [ ] После Delete ресурс больше не доступен ожидаемым способом

## Authorization

- [ ] Запрос без авторизационных данных
- [ ] Запрос с авторизационными данными
- [ ] Некорректные данные авторизации
- [ ] Проверка HTTP-кода и тела ответа при ошибке авторизации

## Postman

- [ ] Переменные коллекции/окружения подставляются корректно
- [ ] Скрипты выполняются без ошибок
- [ ] Tests проверяют ожидаемые свойства ответа
- [ ] Запрос можно повторить в чистом окружении с подготовленными данными

> Чек-лист является учебным материалом. Он не означает, что все перечисленные проверки были фактически выполнены в исходных коллекциях.
