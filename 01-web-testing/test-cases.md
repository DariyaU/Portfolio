# Тест-кейсы

| ID | Сценарий | Ожидаемый результат | Тип |
|---|---|---|---|
| TC-001 | Вход с корректным email и паролем | Пользователь авторизован и перенаправлен в авторизованную зону | Positive |
| TC-002 | Вход с неверным паролем | Авторизация не выполнена, отображается сообщение об ошибке | Negative |
| TC-003 | Вход с несуществующим email | Авторизация не выполнена, отображается сообщение об ошибке | Negative |
| TC-004 | Отправка формы с пустым email | Поле валидируется, вход не выполняется | Negative |
| TC-005 | Отправка формы с пустым паролем | Поле валидируется, вход не выполняется | Negative |
| TC-006 | Отправка формы с обоими пустыми полями | Вход не выполняется, обязательные поля валидируются | Negative |
| TC-007 | Email с некорректным форматом | Пользователь получает сообщение о некорректном email | Boundary/negative |
| TC-008 | Пробелы в начале и конце email | Поведение соответствует согласованным требованиям | Boundary |
| TC-009 | Авторизация по Enter | Поведение соответствует требованиям интерфейса | Functional |
| TC-010 | Обновление страницы после успешного входа | Авторизация сохраняется согласно требованиям | Regression |
| TC-011 | Переход на защищённую страницу без авторизации | Пользователь не получает несанкционированный доступ | Negative |
| TC-012 | Повторная отправка формы | Система корректно обрабатывает повторную отправку | Exploratory |

## Техники тест-дизайна

В наборе использованы позитивные и негативные сценарии, проверки граничных условий и исследовательские проверки. Точные допустимые границы длины полей требуют подтверждения требований и поэтому не выдуманы.
